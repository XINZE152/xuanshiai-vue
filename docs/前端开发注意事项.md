# 前端开发注意事项

> 适用范围：本目录下的 UniApp 工程。更新日期：2026-07-26。

## 1. 开发主线

- 生产实现只在当前工程内完成。
- 微信小程序是第一验收端；H5 只用于快速调试。
- 不新增 HTML 探索稿，不把普通 Web DOM 写法迁入 `.uvue`。
- 开始开发前依次阅读 `../AGENTS.md`、`../PRODUCT.md`、`../DESIGN.md` 和 `PROJECT_STATUS.md`。开发新页面、二级视图、详情页或 Sheet 时，还必须阅读对应上级页面源码并核对色调继承关系。

## 2. 允许与受保护区域

可以按已确认需求修改：`pages/**/*.uvue`、`components/Xsa*.uvue`、`api/`、`mock/`、文档与测试；若需要工具函数可新增 `utils/`（当前目录尚未创建）。

未经明确确认不要修改：`manifest.json`、`pages.json`、`uniCloud-aliyun/`、`uni.scss` 的核心 Token、依赖大版本或第三方库。

## 3. 页面与路由

- Tab 页面使用 `uni.switchTab`，普通页面使用 `uni.navigateTo`，返回使用 `uni.navigateBack`。
- 页面只传必要标识，不把大对象塞入 URL。
- 返回列表后的刷新优先在 `onShow` 评估，不只依赖 `onLoad`。
- 新页面先确认需求和路由评审，不要先写页面再擅自改 `pages.json`。

## 4. 数据与状态

- 页面通过 `@/api` 获取业务数据，不直接导入 `@/mock`。接口与配置开关（含 `EMOTION_LAB_USE_MOCK`）同样只从 `@/api` 取，禁止直接 `import '@/api/xxx.uts'`——`tests/test-role-routing.js` 会守住这条。
- **学历展示只有两套刻度，且不得合并**：用户资料（`user_profile`）1 高中及以下 / 2 大专 / 3 本科 / 4 硕士 / 5 博士，统一调 `utils/profile-field-display.uts` 的 `educationLabel()`；AI 画像旅程（`ai_profile`）是 1 初中及以下 … 6 博士，只能走 `displayFieldValue('education_level', …)`。首页曾自带反序表（1→博士）导致错档，`tests/test-education-label-consistency.js` 已锁死，新增页面不得再写本地字典。
- 己方聊天头像必须用 `getMyAvatarUrl()`（`/auth/me` 缓存 + 退出登录清理），不要写死 `profile-man-light.webp`；对方头像裸路径必须经 `resolveMediaUrl`，空串才回退默认。
- 后端 `Idempotency-Key` 为必填的业务接口（如 `POST /ai/advisor/sessions`，min_length=8）必须在 `request` 的 `headers` 里带上，且同一逻辑操作重试要复用同一个键。
- 列表和详情至少处理加载中、空态、失败和重试。
- 当前全局 `USE_MOCK = false`，用于既有 FastAPI 联调；社区与 `likeUser`/`applyToMeet` 已支持双路径（见 `COMMUNITY_HTTP_CHANGELOG.md`）。消息、父母端和情感实验室仍分别由显式模块开关保持 Mock，关闭前必须完成真实接口、主体鉴权和失败契约联调。
- 父母模块 Mock 也必须绑定有效 token 与当前账号 ID；不能只凭本地 `xsa_onboarding_mode=parent` 读取上下文。退出或 401 后必须清理角色状态，并使页面中旧的父母上下文和异步响应失效。
- 当前社区 1.0 验收使用 `USE_MOCK = false`。社区与 `likeUser`/`applyToMeet` 已支持 FastAPI 双路径（见 `COMMUNITY_HTTP_CHANGELOG.md`）；其它模块仍多为 Mock。切换环境前确认 `API_BASE_URL`、token、后端可达。
- 申请认识是建立沟通关系的前置条件，不能新增陌生人直接私信入口。

## 5. UI 与组件

- 优先复用 `XsaButton`、`XsaCard`、`XsaModal`、`XsaSheet`、`XsaInput` 等现有组件。
- 色彩、字体、间距、圆角和阴影以 `../DESIGN.md` 为准。
- 新页面必须继承上级页面的底色、卡片表面、主强调色、浅强调色、状态色、圆角、阴影和按压反馈。参考图仅复刻布局与信息层级，不得覆盖所属业务域既有色调；变更色调前需获得明确确认并同步更新设计约束。
- 不使用 `window`、`document`、DOM 查询或仅浏览器可用的布局技巧。
- 不把 `../../design-demos/final/` 当生产代码，只参考节奏和视觉关系。

## 6. 修改公共能力时

修改组件、请求封装或全局样式后，至少回归：首页推荐与申请认识、社区列表、牵线列表、消息与申请处理、我的页面及其入口。

## 7. 提交前

- 运行 `node tests/test-mock-system.js`。
- 当前 npm CLI 构建入口未通过，按 `HOW_TO_RUN.md` 使用 HBuilderX 做 H5 预览并记录结果。
- 在微信开发者工具验证关键路径；不要把未执行的端侧验证写成已通过。
- 完成 `开发自检清单.md`。
- 修改代码后从工作区根目录运行 `graphify update .`。
